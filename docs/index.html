02 · Why your CLAUDE.md gets ignored

Rules need scars

You wrote “write clean code” and the model ignored it, because the rule describes a feeling, not a situation. There is no moment where the model can tell it is about to break it. A rule that wins names the exact moment, the exact wrong move, and what it cost.

✗ No teeth, rejected

“Don’t rewrite things unnecessarily.”

A mood, not an instruction. No recognisable moment, no cost, nothing to trigger on.

✓ Carries a scar, merged

“Never replace a whole list to add one item. If an API looks like it can only replace, read its input schema before you believe that. On 2026-08-12 a project board’s status options were replaced twice to add one option each time. Both times the platform silently dropped all 63 card assignments. The input type had an id field the whole time.”

Names the moment, the wrong move, and the cost. All nine rules ship with the dated incident behind them.

03 · Quickstart

Two ways in

Take the plugin for the machinery, hooks included. Take seed.sh when you want the rules too, as files you own and can edit. seed.sh never overwrites an existing CLAUDE.md, .gitignore or .env.example.

Seed a new project
# everything, as files you own
git clone https://github.com/eugnmueller-87/claude-blueprint.git
cd my-new-project
bash ../claude-blueprint/seed.sh .
# then: fill in CLAUDE.md, cp .env.example .env, git init
Or install as a plugin
# hooks, reviewers and skills. Rules and CLAUDE.md stay with seed.sh
/plugin marketplace add eugnmueller-87/claude-blueprint
Test that the machinery works
# a hard-coded key should be blocked (exit 2); a clean env-var reference allowed (exit 0)
echo '{"tool_name":"Write","tool_input":{...}}' | bash .claude/hooks/scan-secrets.sh
